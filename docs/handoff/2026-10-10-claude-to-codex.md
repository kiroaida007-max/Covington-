### Privacy engine (`PrivacyMap.kt`, `TaintEngine`)

Recall (what is followed now):

- **Callbacks** (`callbacks()`): an app object passed to platform or modelled-library code (by
  `dynamicTypes`: its allocation, `this`, or at most three implementations) has its callback methods
  (`interfaceSigs`: DEX interfaces of modelled libraries, `FRAMEWORK_CALLBACKS` for the platform)
  instantiated at the registration: the object as `this`, the registering receiver's data as the
  arguments. Their result joins the call's result when the call returns an object (`withContext`,
  `submit`, `Stream.map`), and a change of the callback's summary re-analyses the registering method
  (`callbackUsers`). Variants of one callback (merged lambdas) are alternatives.
- **Channels** (`CHANNEL_TYPES`) and **storage**: `pref:<key>` and `db:<table>` pseudo-fields
  (`storage()`), with `ContentValues` only (not WHERE arguments) for table writes.
- **Platform alternative**: a virtual call on a platform or library method whose receiver class is not
  known also applies the platform model (`platformToo`), not only the app's overrides.
- **Sinks added**: Paho MQTT `publish`; a `PrintStream` that is not `System.out`/`err` is a file.

Precision (each fixed a measured false-positive class; see the benchmark tables):

- **Two-level access paths**: field keys `a` and `a|b` (`NEST`), `ParField` labels with paths,
  `subst` that refines `q.h` arguments to `q.h.f`, and nested fields of returned values kept as fields.
- **Merged lambda groups per case**: `AppGraph.findDispatch`/`dispatchSwitch` (moved to the companion
  so both ScreenMap and the engine use them) give each switching method one variant per branch
  (`MethodInfo.base/switchAt/branch/cases`; the variant's CFG keeps only its branch). Cases follow
  constructors with a constant id and `this` inside a variant (`allocCases`, `forCases`).
- **Field type sets** (`computeFieldTypes`, `targetsAt`): the classes stored into interface- and
  abstract-typed fields, through parameters of methods only app code can call (`closed`); a call on
  such a field runs only those classes, none if the set is empty. Calls on an object created in the
  method, or on a platform stream (`getOutputStream`), are exact.
- **A call's targets are alternatives**: each starts from the pre-call state, effects joined.
- **A Context carries no app data into platform code** (`passed`); inherited platform methods are
  modelled by their platform class (`platformOwner`); a Location subclass's `getTime()` is metadata.
- **Stream marks** live on the stream's own value (`checkMarks`, `flatten` without nested marks).
- **Convergence**: canonical widening (`P*` subsumes `P.x`, `P.a` subsumes `P.a.b`) and saturating
  bounded summaries (a full list keeps its entries), else summaries oscillated at their bounds.
- **Callbacks carry fields of `this`** only when the registered object is created here (a lambda
  capturing `this.message`), never `this` as a whole (an activity registering itself).

### `PrivacyMap.kt`: summary-based taint analysis (`apkproject privacy`)

Sources, sinks and the rules are in the README section and in `benchmarks/privacy/README.md`,
which tables how each rule moved Tusky from 907 flows (or not finishing) to the correct 0. Design,
for whoever changes it:

- **Labels**: `Par(i)` (value of parameter i), `ParAll(i)` (with all its fields), `ParField(i, f)`,
  sources and markers (content URIs, network and file streams). Register values are
  `RV(whole, fields, alias, holder, holderField)`. `alias` is the object identity: a parameter
  index or an allocation site. Mutations update every register with the same alias and report a
  parameter's object in the summary. A value read from a field keeps its holder, so mutating it
  (`this.sb.append(x)`) adds to that field of the holder.
- **Summary**: return value (with its alias), `paramOut`, symbolic `fieldWrites`, and sink edges
  (per parameter and sink kind/detail: the labels that reach it and the shortest call chain). It is instantiated at each call. Callees go first
  (Tarjan SCCs); a priority worklist re-analyses callers when a summary changes and readers when
  a shared field changes. Each new summary is joined with the old one, so iteration terminates.
- **Shared (field-based) taint**: only for value-typed fields (strings, `double`, `Location`, flat
  data classes), and one hop (`viaField` labels are not stored again). This is the part that
  decides precision; read the benchmark before widening it.
- **Modelled, not analysed**: platform and well-known library packages (`MODELLED`). External calls
  move receiver + arguments to the result. Containers and builders absorb their arguments
  (`absorbs`). `toString` reads the fields; boolean and size-like results carry nothing.
- **Permissions**: a flow whose source needs a permission the manifest does not request is
  `permissionDeclared = false`, LOW, and left out of the Data safety rows.
- **Tusky 32.2**: 31,764 methods analysed (5,617 modelled), about 39,400 analyses, 16–17 s,
  0 flows. Two library sources are reported, and the location permission is not requested. It fits
  a 1 GB heap. 1,167 summaries reached a size bound (`stats.boundedSummaries`). With the earlier
  per-call-site edges, raising the bound from 48 to 512 took 44 s and still left 1,872 bounded.

- **Full `decompile` of Tusky** with both new steps: same compile and round-trip numbers as before

## JADX 1.5.6 pitfall (cost two regressions; read before renaming anything)

JADX checks same-package simple-name collisions **against original names**. Whenever a mapping
gives a class a simple name equal to another class used in the same file, JADX may write
`import q.N;` and use bare `N` for both. That happens if the same-package class was renamed,
or if its package was moved. Measured on Tusky:

- moving packages (`k1` → `k1_`): 922 files, 3,100 errors;
- one new name per root (`k1_` twice): +6,600 errors.

Rules now in `NameMapping`:

- never move packages;
- every renamed type gets a name unique among all class simple names the DEX refers to, framework
  types included (`Notification` next to `android.app.Notification` becomes `Notification_ha`).

`MethodNamingIntegrationTest` reproduces both failures; each test fails on the old behaviour.
